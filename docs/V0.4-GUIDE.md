# Files, browser IDE, runtime versions and panel updates

## File manager

Choose an application under **File manager**. Use the folder sidebar and breadcrumbs to navigate. Click a text file to open the editor; select rows for rename, copy, move, download, permissions or Trash. Copy/Move followed by Paste works across folders within the same application. Enable **Hidden files** to see dotfiles. Trash retains items under `.cgpanel-trash`; move them back to restore. It is not an off-server backup and has no automatic expiry.

Uploads support drag-and-drop and multiple files, with progress and cancellation. Files are staged until the upload finishes; replacing an existing file requires an explicit overwrite choice. The per-file limit is 2 GiB. Downloads stream to disk in browsers supporting the File System Access API; other browsers use a Blob download limited to 128 MiB. Use SFTP for larger downloads in those browsers.

The editor supports UTF-8 text up to 256 KiB, line numbers, find/replace, Tab indentation and Ctrl/Cmd+S. Saving checks the content revision and refuses to overwrite a file changed since it was opened. Binary files and symbolic links cannot be edited. Use code-server for larger source files. Directory listings show 400 entries per page, with filtering of the visible page.

File operations work while the app is stopped. A Rust helper runs as the tenant's OS identity and walks directory file descriptors without following symlinks. Parent traversal, hardlink reads/writes and special files are rejected. Copy is limited to 10,000 entries and 1 GiB. Permissions are restricted to ordinary modes without setuid/setgid bits. Compress creates ZIP archives, and Extract expands ZIPs into a new folder. Both are limited to 10,000 entries and 1 GiB uncompressed content. Extraction rejects path traversal, symlinks and special files, and never overwrites an existing destination folder. Other archive formats are not supported.

## Workspace IDE

Open **Workspace IDE**, select **Install code-server**, and follow its background job. **Open IDE** reveals its password to the signed-in owner/administrator and links to the IDE. Password retrieval is session-only. **Reset password** recreates it with a new secret. **Stop IDE** frees its memory while preserving settings, extensions and files.

code-server uses a dedicated rootless container, a 384 MiB memory cap, and a separate HTTPS origin on a unique port for each workspace. Its own password authentication remains enabled. It shares only the selected application's workspace and its private IDE settings directory; it has no host root access, host socket or privileged container access. Separate workspace origins prevent one IDE’s scripts from reading another IDE or the panel API. Only enabled IDE ports are allowed through the firewall. Stop IDEs on memory-constrained servers when not in use. Disabling a tenant account stops its IDE containers.

Git and the editor terminal are available inside code-server. Configure your own Git identity and repository credentials there; they are not panel administrator credentials. Commit and push only files intended for your repository. Language tools installed inside the IDE are separate from the application's selected production runtime. The certificate on the IDE origin follows the panel's IP certificate; initial self-signed panel installations also require trusting that certificate before opening the IDE.

## Runtime versions

Open **Runtime versions** to select versions per application: PHP 8.2–8.5, Python 3.11–3.14, Node.js 22/24, Java 17/21/25, and Rust stable. Static sites use a selected Python HTTP-server runtime. These are version tracks; upstream patch releases may change. Existing/custom runtimes are preserved during panel upgrades.

Changing a version is a background job. The new image is prepared before stopping the old container. The workspace, environment and assigned port are retained. A new container that does not remain running after startup is rolled back to its previous container. This is a startup check, not an application compatibility test. File/database changes made by a newly started application are not reversed. Take a full backup before production language upgrades.

PHP version profiles provide CLI, FPM, PDO MySQL, MySQLi and OPcache. Their FPM launcher is `/usr/local/bin/cgpanel-php-start`, serving `/workspace/public`; the compatibility alias `/usr/local/bin/lunar-start` is retained. An empty startup command keeps the original runtime starter behavior. Move an older site's public files into `public/` before adopting the FPM launcher. Python dependencies/virtual environments may need rebuilding after interpreter changes. Disable an outgoing proxy before changing runtime, then re-enable it after validation.

## Automatic updates — administrator only

**Panel updates** can check, install, enable or disable automatic updates. Automatic updates are enabled on v0.4 installation and checked every six hours with a randomized delay. Disabling the switch prevents scheduled installations; a manually requested installation still works.

The updater uses published, non-prerelease stable tags in `ItzGlace/CGPanel` on GitHub, not arbitrary main-branch commits or a user-supplied repository. The x86_64 binary bundle's SHA-256 is verified against its release asset. This trusts GitHub HTTPS and the repository's release publisher; the checksum is not an independent signature. Targets do not compile Rust or npm packages during an update.

An update defers while background jobs are running. When idle, it stops panel/broker services, snapshots their binaries, SQLite database and broker registry under `/var/backups/cgpanel-*`, installs the release and checks `/healthz` and both services. A failed apply restores the previous binaries, database and registry and attempts to restart them. Tenant app containers are not recreated by panel upgrades. Backups remain on disk for administrator-managed retention.

Root-owned settings: `/etc/cgpanel/updates.json`. Status: `/var/lib/cgpanel-updates/status.json`. Units: `cgpanel-auto-update.timer`, `cgpanel-auto-update.service`, `cgpanel-update-check.service` and `cgpanel-update.service`. Inspect service journals for failed downloads or rollback. A successful process health check cannot prove every website feature works; monitor applications after upgrades.

## API examples

All endpoints use the panel's existing ownership, session/CSRF and administrator-token rules. Replace `APP_ID` with an owned application ID.

| Endpoint | Request |
| --- | --- |
| `POST /api/v4/files/APP_ID` | `{"operation":"list","path":"public","offset":0}` |
| `POST /api/v4/files/APP_ID` | `{"operation":"read","path":"public/index.php"}` |
| `POST /api/v4/files/APP_ID` | `{"operation":"save","path":"public/index.php","content":"...","revision":"HASH_FROM_READ"}` |
| `GET /api/v4/runtimes` | Approved version catalog |
| `GET /api/v4/runtimes/APP_ID` | Current runtime, version, image and startup command |
| `POST /api/v2/jobs` | `{"kind":"runtime","target":"APP_ID","version":"3.14","command":""}` |
| `GET /api/v4/ide/APP_ID` | Installed/enabled state and URL |
| `POST /api/v2/jobs` | `{"kind":"ide","target":"APP_ID","enabled":true}` |
| `POST /api/v4/ide/APP_ID/password` | `{}`; session only, returns the IDE password |
| `GET /api/v4/updates` | Administrator-only settings/status |
| `POST /api/v4/updates` | `{"action":"settings","enabled":false}` or `{"action":"check"}` or `{"action":"apply"}` |

File operations also include `archive`, `extract`, `touch`, `mkdir`, `move`, `copy`, `trash`, `chmod`, `download`, `upload_begin`, `upload_chunk`, `upload_finish`, and `upload_cancel`. Paths are workspace-relative; `path:""` lists the root. Copy/move need `destination`; chmod needs a three-digit `mode`. Download uses byte `offset` and returns base64 `data`, `next`, `size`, and `done`. Upload begin uses the final destination `path` and returns `upload`; chunk calls use that ID, a matching byte offset and base64 data up to 192 KiB. Finish uses the same destination/ID and optional `overwrite:true`; cancel removes its staging file. All calls require the application's owner or an administrator. Read-only bearer tokens cannot invoke POST file operations.
