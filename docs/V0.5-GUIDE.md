# CGPanel 0.5 workspace guide

## Start with an application

An application is a project workspace, its language runtime, environment variables, and startup command. Use **Web** for websites, APIs or webhook bots and **Worker** for background jobs or polling Telegram bots. A domain points visitors to a web application. Databases and mailboxes are managed separately.

The first-login guide explains each visible section. Replay it with **Quick tour**. The CGPanel logo links to the public GitHub repository.

## Allocate resources and choose a runtime

Administrators set each account's RAM, CPU and workspace disk budget. **Overview** shows remaining allocation, not instantaneous physical RAM usage. Applications reserve their selected limits; an enabled IDE also reserves 384 MiB RAM and 750 CPU millicores. One CPU core equals 1,000 millicores.

New workspaces use bounded filesystem volumes. Existing workspaces show whether disk enforcement is active; apply a disk allocation to migrate them while the application is running. Migration briefly pauses the app and IDE and retains a recovery copy. Volumes can grow; shrinking requires migration. Databases, mail and container images use separately managed server storage. Filesystem metadata consumes part of the allocated workspace capacity.

**Runtime versions** offers supported tracks and custom official image tags. `tag:3.14-slim-bookworm` is an example Python tag; PHP tags must be FPM variants. Only the panel's approved image repositories are used. Historical tags may be unavailable or unsupported; changing versions does not make incompatible code or dependencies work automatically. The previous runtime remains available for rollback until you resolve it.

## Transfer files and edit code

**Services** enables SFTP on port 22 or explicit TLS FTPS on port 21 with passive ports 60000–60100. Both use an application transfer account and workspace, with optional IP/CIDR restrictions. New or rotated passwords appear once. Plain FTP is disabled. Existing eligible SFTP accounts retain their credentials during migration.

**File manager** supports folders, uploads, copying, moving, archives, permissions and Trash. Open a text file to edit it in a separate tab. Enable **Auto-save · 10s** to save dirty text every ten seconds. Revision checks reject conflicting changes; review and reload before overwriting another editor's work. Text editing remains limited to 256 KiB. Hover previews cover supported images/videos up to 8 MiB; active SVG/HTML files are excluded.

**Workspace IDE** installs code-server only for the selected workspace. It includes Git, an interactive terminal and extension installation. The panel's Git buttons provide status, recent history, change statistics and repository initialization. Run full Git workflows inside the IDE. Domain-based IDE access uses HTTPS port 8443 because common CDN proxies support it; it remains on a separate origin from the panel. Configure a trusted domain certificate for strict CDN TLS validation.

## Console, logs and scheduling

**Terminal** streams stdout and stderr and reports the command exit code. Tab completes installed command names, arrow keys recall history, and `clear` or Ctrl+L clears the output. Commands run in the application container without host root and stop after 25 seconds. Use the IDE terminal for interactive programs.

**Program logs** shows the selected application's recent stdout/stderr with automatic refresh. Configure PHP or your framework to emit errors there; private log files are not automatically discovered.

**Scheduled tasks** has common timing presets, timezone-aware next-run previews, execution history, and **Run now**. Testing executes the real command and can change data. It does not merely check syntax. Run-now tests use the bounded terminal execution limit.

## Restore a backup

Upload an owned `.cgp` file or choose a local full backup, select restore, and type `RESTORE`. Uploaded archives are limited to 2 GiB and must match the existing account and application IDs. Cross-server/account imports require administrator-assisted migration.

The panel creates a recovery archive before modifying data. It pauses the application, IDE and transfer access, replaces workspace contents with the archive, and restores selected MySQL/PostgreSQL dumps under their database identities. Files added after the backup are removed. Writers resume even when restore fails; the error identifies the recovery archive. SQL dumps do not form a single transaction across multiple databases.

Domain/DNS configuration is included in the archive manifest for review; existing domain assignments remain intact. Mailbox messages are not included in application backups. Keep independent off-server copies and test recovery before relying on any backup.

## Analytics, protection and indexing

Enable analytics for an owned domain and install the generated tracker. Unique IP counts are estimates, not a count of people. Shared addresses, blockers, Do Not Track and browser privacy settings affect results. Click heatmaps represent recorded normalized click locations.

In **Website protection**, start OWASP CRS in detection mode, review requests and test the site before switching to enforcement. Per-IP request/connection limits and recent rejection/error summaries help investigate unwanted traffic. A suspicious-source flag is a heuristic, not proof of an attack. Host controls cannot absorb traffic that saturates the upstream network connection; arrange provider/CDN protection for that case.

Crawler controls block matching declared user agents and publish robots.txt. They cannot identify every disguised bot. A sitemap can use explicitly entered paths or automatically include paths observed by analytics. Only enable automatic mapping if tracked pages are public: private route names would otherwise be published. Query strings are excluded, and output is bounded to 1,000 paths.

**CAPTCHA** supports local arithmetic challenges, Cloudflare Turnstile, hCaptcha and Google reCAPTCHA. Provider site keys and secrets must match the website hostname. Verification is checked server-side; local challenges are single-use and visitor passes are bound to the domain and IP. This site-wide gate can disrupt API clients and webhooks. Simple arithmetic is a basic friction mechanism, not a guarantee against automated solvers.

IP filtering accepts CIDR prefixes and shows their first and last address. PostgreSQL supports IPv4/IPv6 networks; MariaDB supports IPv4 netmasks and individual IPv6 addresses.

## Account security and mail

Enable authenticator MFA in **Account settings**, verify a code, and save the recovery codes privately. Each recovery code works once. Enrollment and disabling require the current password; disabling also requires a valid second factor. Existing administrator API tokens remain independent credentials and should be reviewed/revoked if account access is in doubt.

See [Mail hosting](MAIL.md) for real SMTP/IMAP mailboxes, quota management, public DNS, certificates, reverse DNS and API examples. Each VPS needs its own mail-host setup.

## Updates

Administrators can enable or disable automatic updates from stable GitHub releases. Checks do not install prereleases. Updates wait for running background jobs, verify the bundle checksum, save recovery state, and require the new version's health check. The rollback snapshot is root-only under `/var/backups`. Application data still needs independent backups. This community alpha has not received an independent security audit.
